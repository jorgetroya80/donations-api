# Spec: Audit Log (who + when per change)

Source idea: [`docs/ideas/audit-log.md`](ideas/audit-log.md)
Decision record: [ADR-006](decisions/ADR-006-audit-log.md)

## Objective

Let the church prove to an external auditor or the tax authority **who created or changed each donation, expense, donor and user, and when — for every change, not only the latest one** — without storing donor personal data a second time.

Today `AuditableEntity` stamps `created_by/at` and `updated_by/at` on each row (verified working locally on 2026-11-23), but `updated_by/at` is overwritten on every edit, so earlier changes are lost. This feature adds an append-only `audit_log` table holding one row per write.

**User stories**

- As the treasurer, when an auditor asks "who touched donation 573 and when?", I can answer with the complete, ordered list of changes.
- As an admin, I can see every change made to a user account (creation, admin edits, self-service password change).
- As a developer running the test seed script, seeded rows show `seed` as their origin instead of having no history.

**Decisions already made**

| Decision | Choice |
|---|---|
| Mechanism | App-written table in the same transaction (not Envers, not DB triggers) |
| Content | Entity type, entity id, operation, username, user id, timestamp. **No field values, no diffs** |
| Actor identity | Username **and** user id: usernames can be renamed and reused, the id cannot. `performed_by_id` is null for `system` and `seed` |
| Allowed values | `entity_type` and `operation` are restricted by DB `CHECK` constraints, so manual SQL and the seed script cannot store typos |
| Operations | `CREATE`, `UPDATE` (no delete endpoints exist) |
| Self-service password change | Audited as `UPDATE` on `USER` |
| No-op update (PUT that changes nothing) | Still recorded as `UPDATE` by the submitter: `UPDATE` means "an update request was accepted". Hibernate skips the row write, so `updated_by` keeps the previous user |
| Read access | SQL only, run by an admin. No API endpoint in this scope |
| Seed script | Writes its own `audit_log` rows with `performed_by = 'seed'`; the `V3` admin seed is excluded |
| Existing data | Not backfilled. Current `created_*/updated_*` columns remain the baseline for pre-existing rows |

### Schema

```sql
CREATE TABLE audit_log (
    id              BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    entity_type     VARCHAR(20)  NOT NULL CHECK (entity_type IN ('DONATION', 'EXPENSE', 'DONOR', 'USER')),
    entity_id       BIGINT       NOT NULL,
    operation       VARCHAR(10)  NOT NULL CHECK (operation IN ('CREATE', 'UPDATE')),
    performed_by    VARCHAR(100) NOT NULL,
    performed_by_id BIGINT,
    performed_at    TIMESTAMPTZ  NOT NULL
);

CREATE INDEX idx_audit_log_entity ON audit_log (entity_type, entity_id);
```

No foreign keys to the audited tables: the log must survive if a row is ever removed.

### Write points (one `record` call each)

| Service method | entity_type | operation |
|---|---|---|
| `DonationService.createDonation` | DONATION | CREATE |
| `DonationService.updateDonation` | DONATION | UPDATE |
| `ExpenseService.createExpense` | EXPENSE | CREATE |
| `ExpenseService.updateExpense` | EXPENSE | UPDATE |
| `DonorService.createDonor` | DONOR | CREATE |
| `DonorService.updateDonor` | DONOR | UPDATE |
| `UserService.createUser` | USER | CREATE |
| `UserService.updateUser` | USER | UPDATE |
| `UserService.changeOwnPassword` (success path only) | USER | UPDATE |

Each call sits next to the existing `eventLogger.emit(...)` for that write. A failed password change writes nothing.

## Code Style

Match the existing code: constructor injection, `@Transactional` on the service write methods, small focused classes, KDoc only where the *why* is not obvious.

```kotlin
package com.example.donations.infrastructure.audit

import com.example.donations.user.UserRepository
import org.springframework.data.domain.AuditorAware
import org.springframework.stereotype.Service
import org.springframework.transaction.annotation.Propagation
import org.springframework.transaction.annotation.Transactional
import java.time.Instant

/**
 * Appends one row per write to audit_log. Callers are already inside the write's
 * transaction, so the audit row commits or rolls back with the change itself;
 * MANDATORY makes a call site without a transaction fail loudly instead of
 * committing the audit row on its own. Stores identifiers only — never field
 * values (ADR-005, ADR-006). The user id is kept beside the username because
 * usernames can be renamed and reused; it is null for "system".
 */
@Service
@Transactional(propagation = Propagation.MANDATORY)
class AuditService(
    private val auditLogRepository: AuditLogRepository,
    private val auditorAware: AuditorAware<String>,
    private val userRepository: UserRepository,
) {
    fun record(entityType: AuditEntityType, entityId: Long, operation: AuditOperation) {
        val username = auditorAware.currentAuditor.orElseThrow()
        auditLogRepository.save(
            AuditLogEntry(
                entityType = entityType,
                entityId = entityId,
                operation = operation,
                performedBy = username,
                performedById = userRepository.findIdByUsername(username),
                performedAt = Instant.now(),
            ),
        )
    }
}
```

Call site:

```kotlin
val saved = donationRepository.save(donation)
auditService.record(AuditEntityType.DONATION, saved.id!!, AuditOperation.CREATE)
eventLogger.emit(DonationCreated(saved.id!!, saved.donor?.id, saved.amount))
```

Conventions:
- Enums stored as strings (`@Enumerated(EnumType.STRING)`), upper-case values.
- `AuditLogEntry` does **not** extend `AuditableEntity` — an audit row is never updated, so it has no `updated_*` columns.
- Username comes from the existing `AuditorAware` bean, so `audit_log.performed_by` matches `created_by`/`updated_by` on the row whenever the update actually changed a field (see no-op updates above).

### Seed script addition (before `COMMIT;`)

```sql
-- Audit origin for seeded rows. created_by IS NULL identifies rows inserted by
-- this script (the app always sets it); NOT EXISTS keeps re-runs from duplicating.
INSERT INTO audit_log (entity_type, entity_id, operation, performed_by, performed_at)
SELECT 'DONOR', d.id, 'CREATE', 'seed', now() FROM donors d
WHERE d.created_by IS NULL
  AND NOT EXISTS (SELECT 1 FROM audit_log a WHERE a.entity_type = 'DONOR' AND a.entity_id = d.id);
-- same for DONATION (donations) and EXPENSE (expenses)
```

## Testing Strategy

Integration tests in `src/test/kotlin/com/example/donations/AuditLogTest.kt`, following the pattern of `DonationRecordingTest.kt`: `@SpringBootTest`, `@AutoConfigureMockMvc`, `@Import(TestcontainersConfiguration::class)`, real HTTP calls through MockMvc with `TestAuth` sessions, assertions on `AuditLogRepository`.

Test cases (write first, watch them fail, then implement):

1. Create a donation as `operator1` → exactly one row `(DONATION, id, CREATE, operator1)`.
2. Create, then update a donation → two rows in order `CREATE`, `UPDATE`; first update's user is preserved after a second update by another user.
3. Same CREATE/UPDATE pair for expense, donor, and user (admin-created user).
4. Self-service password change → one `(USER, id, UPDATE, <that user>)` row; wrong current password → no new row.
5. Rejected write (validation error, 4xx) → no audit row.
6. `performed_by` equals the row's `updated_by` after an update that changes a field; a no-op update records the submitter while `updated_by` is unchanged.
7. A write that fails at commit (after the audit insert) leaves no audit row; `AuditService.record` outside a transaction throws `IllegalTransactionStateException`.

Existing tests must stay green: `./gradlew test`.

Manual check for the seed change: run the seed script against an empty Compose DB after V9 is applied, then `SELECT entity_type, count(*) FROM audit_log WHERE performed_by = 'seed' GROUP BY 1` returns 100 donors, 606 donations, 38 expenses (current seed sizes). A full re-run aborts on duplicate `national_id` before reaching `audit_log`; re-running only section 9 adds no new `seed` rows.

## Boundaries

**Always**
- Write tests before the implementation for each write point.
- Keep the audit insert inside the same `@Transactional` method as the change.
- Run `./gradlew test` before reporting a task done.
- Store only identifiers and usernames in `audit_log`.

**Ask first**
- Any schema change beyond `V9__create_audit_log.sql` as specified.
- Adding a dependency (e.g. Envers).
- Adding a read endpoint, export, or UI.
- Auditing reads, logins, or anything outside the nine write points above.

**Never**
- Edit applied migrations `V1`–`V8` (including `V3__seed_admin_user.sql`).
- Store field values, donor names, national IDs, emails, or addresses in `audit_log`.
- Add `UPDATE` or `DELETE` code paths for `audit_log`.
- Run `git commit` — Jorge commits.

## Success Criteria

- [x] `V9__create_audit_log.sql` applies cleanly on a fresh DB and on the existing local DB.
- [x] All nine write points produce exactly one audit row with the correct entity type, id, operation and username.
- [x] A write that fails or rolls back produces no audit row.
- [x] `AuditLogTest` passes; full `./gradlew test` passes.
- [x] Seed script produces `seed` audit rows for donors, donations and expenses only, and re-running the audit section does not duplicate them.
- [x] ADR-006 written and indexed in `docs/decisions/README.md`.
