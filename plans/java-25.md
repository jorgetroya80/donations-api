# Implementation Plan: Java 24 → Java 25 (LTS)

## Overview

Move the project from Java 24 to Java 25. Java 24 is a non-LTS release that stopped receiving
updates when 25 shipped (September 2025), so production on Render currently runs a JRE with no
security patches. Java 25 is an LTS release.

No application behaviour should change. Success is: same tests, same build output, new JDK in
every place the version is pinned.

## Where Java 24 is pinned

| Place | Line | Effect |
|---|---|---|
| `build.gradle` | toolchain `JavaLanguageVersion.of(24)` | compile + test JDK, Kotlin `jvmTarget` |
| `Dockerfile` | `eclipse-temurin:24-jdk-noble`, `eclipse-temurin:24-jre-noble` | build image + **production runtime** (Render) |
| `.github/workflows/ci.yml` | `setup-java` `java-version: 24` | CI `./gradlew check` |
| `.github/workflows/release.yml` | `setup-java` `java-version: '24'` | release job |
| `.tool-versions` | `java temurin-24.0.2+12` | local JDK picked by asdf/mise |
| `README.md`, `CLAUDE.md` | "Java 24" | docs only |

Historical records (`docs/PRD-*.md`, `docs/donor-search.md`, older `plans/*.md`) also say Java 24.
They describe the project at the time they were written and stay unchanged; `docs/donor-search.md`
still says Kotlin 2.2 for the same reason. `CHANGELOG.md` is generated by release-please.

## Compatibility

- **Gradle 9.4.1:** runs on and targets Java 25 (support since 9.1). No wrapper change.
- **Kotlin 2.4.20:** supports `jvmTarget` 25 (since 2.3). No change.
- **Spring Boot 4.0.5 / Spring Framework 7:** supports Java 17–25. No change.
- **Hibernate, Flyway, Jackson 3, Testcontainers 2:** bytecode-level only, no known Java 25 issues.
- **GraalVM native (`org.graalvm.buildtools.native` 0.11.5):** a native build needs GraalVM for
  JDK 25. No CI job builds native today, so this only affects a local `nativeCompile`.

## Architecture Decisions

- **No ADR.** Same treatment as the Kotlin 2.4.20 upgrade: a version bump with no change to the
  stack or to the public API. If Jorge sees it as a "major dependency" decision, write ADR-006.
- **No toolchain auto-provisioning.** `settings.gradle` has no foojay resolver, so Gradle only
  uses JDKs installed on the machine. Install Temurin 25 locally instead of adding a plugin.
- **No source changes expected.** If the upgrade requires editing application code, that is a
  finding to report.

## Task List

### Task 1: Install JDK 25 locally — done (asdf temurin-25.0.1+8.0.LTS)

Local machine has Temurin 24 on PATH and OpenJDK 26; no 25.

- `brew install --cask temurin@25`
- **Verify:** `/usr/libexec/java_home -v 25` prints a path.

### Task 2: Bump the toolchain — done (208 tests green, bootTestRun UP)

- `build.gradle`: `JavaLanguageVersion.of(24)` → `of(25)`.
- **Verify:** `./gradlew clean check` passes (same test count as on `main`). Then `./gradlew
  bootTestRun` starts and logs `Started DonationsApplicationKt`.
- Testcontainers flakes at context load: re-run once before investigating.

### Checkpoint: build + tests green on 25

### Task 3: Docker image — done (Temurin 25.0.4.1 image, liveness UP)

- `Dockerfile`: both stages `24` → `25` (`eclipse-temurin:25-jdk-noble`, `eclipse-temurin:25-jre-noble`).
- **Verify:** `docker build -t donations:java25 .` succeeds; run it against the Compose
  PostgreSQL and hit `/actuator/health/liveness` → `UP`.

### Task 4: CI workflows — done (actionlint clean; CI run pending on PR)

- `ci.yml`: step name and `java-version` → 25.
- `release.yml`: `java-version` → `'25'`.
- **Verify:** CI on the PR passes.

### Task 5: Docs and local version pin — done (only historical records still mention Java 24)

- `README.md:7`, `README.md:34`, `CLAUDE.md:77`: "Java 24" → "Java 25".
- `.tool-versions`: `temurin-24.0.2+12` → the installed Temurin 25 build.
- **Verify:** the repo-wide search for "Java 24", "Temurin 24" and "java-version" only finds the
  historical records listed above.

### Checkpoint: PR ready

- One PR, `feat: upgrade Java to 25`, so release-please produces a minor bump.
- After merge, Render auto-deploys the new image: check `/actuator/health/liveness` in production.

## Risks

| Risk | Likelihood | Mitigation |
|---|---|---|
| Render free plan memory with new JRE | Low | `-XX:MaxRAMPercentage=75.0` unchanged; watch first deploy |
| Library warning/failure on Java 25 | Low | Task 2 catches it before Docker/CI |
| Native image broken locally | Medium, unused | Out of scope; note only |

## Rollback

Revert the PR. Render redeploys the Java 24 image.
